# AI 小说工坊（ai-novel）

本地运行的长篇网文 AI 辅助写作应用。Rust 编写，编译出来就是一个可执行文件：桌面版双击就在自己的窗口里打开，也可以用浏览器版，数据全部存在本机。定位是替代酒馆（SillyTavern）来写小说：开新书、续写旧稿、长篇记忆、文风控制、按番茄/起点格式导出。

原则是**作者主导剧情，AI 负责起草、续写、润色和记账**。

## 功能

**开新书**：六步向导。选平台和题材、写一句创意 → AI 给 3 个开书方案 → 世界观 → 主要人物 → 总纲 → 第一卷章纲，每一步都能改、能跳过。开篇三章内置“黄金三章”写作要求。

**写作**
- 两段式写章：先「AI 规划节拍」把本章拆成 5～8 个场景（含爽点三段式和章末钩子类型），改完再「写整章」，AI 按节拍逐个写
- 续写（从光标处）、写整章、扩写、缩写、改写、润色；勾选「大结局」时自动列出所有未回收伏笔要求收束
- 一次生成 1～3 个版本对比挑选，可以随时停止；扩写/改写/润色的结果可以切到**修订模式**，按句逐条决定采纳哪些修改
- **AI 校对**：整章或选中段落只找错别字、的地得、病句和标点，不润色；长章节按段落分块校对，结果直接进修订模式，每处修改点一下就能改回原文；设定名和境界会告诉模型原样保留，删掉超过 3% 或设定词被改掉会提醒
- 放进正文前自动存快照，随时可以在「历史」里恢复
- 拆章 / 合并：在光标处把一章拆成两章（后半移到紧跟着的新章节），或把下一章接到这一章后面；合并时下一章的历史版本、设定状态、伏笔和揭示进度都转过来，两章原文先存快照
- 发布状态：目录里每章右侧的「发」把这一章和前面的章节标成已发布，「撤」取消；统计里显示存稿章数、字数，填了每天更新字数还会算出存稿够更几天
- 37 个题材模板（核心基调、节奏、反套路）自动注入写作提示；12 篇写作手册（爽点、钩子、冲突、润色、去 AI 腔等）可以随时翻看
- 所有提示词都能在「设置 → 编辑提示词模板」里修改，生成前可以「查看将要发送的提示词」
- 批量起草：给“有章纲、没正文”的章节依次规划节拍、写出初稿（保持草稿状态，需要作者逐章审改）
- Ctrl+K 命令面板：搜索命令、跳转章节、打开设定

**编辑器助手**
- 灰字续写：按 Ctrl+Enter，AI 在光标处给出一两句灰色的续写；Tab 采纳、Ctrl+→ 逐句采纳、Esc 取消、Ctrl+Enter 换一个，接着打字时灰字会跟着走。可以在设置里改成停顿后自动出现。采纳后能用 Ctrl+Z 撤销
- 斜杠指令：在新的一行打 `/`（中文输入法下打 `、` 也行），选环境描写、人物描写、动作打斗、心理活动、对话、爽点、转场、章末钩子、润色上一段、扩写上一段、起名、规划节拍；支持拼音缩写（`/hj` 环境、`/dz` 打斗），指令后空一格可以写要求（`/dz 一招制敌`）
- 设定名高亮：正文里的人名、地名、物品、势力按类别着色，鼠标停在上面显示设定和当前状态，Ctrl + 点击打开设定；打 `@` 从设定库里挑名字插入
- 选中一段文字会浮出工具条：润色、校对、扩写、精简、按要求改写，或者收藏到文风库
- 设定名排除短语：设定条目可以填「排除短语」（比如人名「白山」排除「白山羊」），高亮、记忆匹配和体检都会跳过

**文风库**（让 AI 学你的写法，越用越像你）
- 收藏范文：自己的得意段落、喜欢的作者的片段都可以，粘贴、导入 txt/docx/epub（可按章拆开），或在编辑器里选中后一键收藏
- AI 分析：每篇范文好在哪里、具体写法、节奏和对话特点、仿写要点，并给片段打上场景标签（打斗、对话、环境、爽点、章末钩子……）
- 写作时自动参考：续写、写整章、润色、灰字、斜杠指令会按当前场景从文风库检索几段范文给 AI 参考（关键词 + 场景标签 + 题材；配置 Embedding 接口后加上向量检索），生成结果会标出参考了哪几篇
- 文风指南：AI 综合范文分析、范文的句长和对话统计，以及**你对 AI 文字的修改**（把什么改成了什么、删掉了什么），提炼成一份文风指南，自动带进每次写作；可以手改，保留历史版本，可按题材分别维护
- 学习记录：你采纳 AI 文字后又改过的地方都会记下来，下次提炼指南时告诉 AI 你的口味
- 照抄检测：正文和文风库范文连续 16 字以上相同会在文字检查里标出来（从本书收藏的片段除外），避免投稿时撞上原文
- 「问问编辑」：带着全书上下文讨论剧情
- 自动保存、日更字数统计、专注模式、深色主题、整屏阅读模式（左右方向键翻章）
- **朗读校对**：阅读模式里点「朗读」，从屏幕上看到的位置开始逐句朗读并高亮，读完自动翻到下一章；点哪句就从哪句读，听到不对的地方点「去改这句」回到编辑器并选中这一句（用系统语音，Windows 自带中文语音）
- 手机上也能用：章节和 AI 面板变成左右抽屉，弹窗从底部升起，见下面「手机版」

**长篇记忆**（AI 写长篇最难的部分）
- 设定库：人物、势力、地点、物品、体系；每条有「不可改变的特征」和「当前状态」。正文或章纲里出现名称或别名时自动带进上下文，主角这类条目可以设为常驻
- 人物状态结构化：位置、实力、身体、心理、关键物品、近期经历、知道的秘密、还不知道的事
- 人物关系：定稿时自动提取，写作时注入出场人物之间的关系（已结束的关系会标注），可视化关系图里可以编辑
- 人物推演：主要人物按各自目标和已知信息推演下一步，给章纲找素材
- **设定随章节演变**：状态按章节存历史，写第 N 章时只用第 N 章之前的状态，回头改前文不会泄露后面的剧情
- 分层摘要：章摘要 → 卷摘要，写后面的章节时自动回顾前情
- 伏笔台账：埋在哪章、计划第几章回收、最近一次推进；逾期和沉寂会提醒
- 前文检索：用中文二元组 BM25 找出和本章相关的旧章节片段（不需要向量模型）
- 定稿：每章写完点一次，AI 生成摘要、找出人物状态变化和新伏笔、分析张力和爽点，你核对后一键写回；导入旧稿后可以「批量定稿 / 建档」
- 可以随时查看「AI 写这一章时能看到的上下文」

**检查**
- 连续性体检（本地规则，免费）：伏笔逾期和沉寂、主要人物长期缺席或从未出场、已死亡人物出场、人物设定单薄、定稿缺摘要、连续张力偏低、爽点断档
- 文字质量（本地规则，免费）：套话和 AI 腔、解释腔和上帝视角、弱化副词密度、意义膨胀、万能结论、句首重复、重复表达、长段落、半角标点、对话占比、句长节奏，以及和前 10 章的跨章重复、开头结尾雷同，点击定位到原文
- 设定一致性检查（AI）：能力等级、死人复活、称呼错乱、时间线冲突、人物 OOC
- 编辑审稿（AI）：开头、节奏、爽点、人物、章末钩子、可读性打分和改法
- 冷读者反馈（AI）：假装没看过设定的新读者，说哪里被吸引、哪里想跳过、还想不想看下一章
- 修订计划（AI）：结合已有的检查结果，整理成按优先级排序的修改清单
- 开篇体检（本地规则）：主角有没有在第一章前 300 字出场、金手指（在作品设定里填）有没有在前 1000 字亮出来、前三章有没有章末钩子
- 敏感词检查（本地词库）：涉政、色情、血腥暴力、毒品、赌博、枪支爆炸物、引流广告（QQ、微信、手机号、网址）、低俗辱骂，按风险分级并给出改法；可以在设置里追加词（`词=改法`）、导入词库文件、把误报加进「不再提示」；结果并入文字检查和投稿检查
- 一键修正标点：英文引号、半角标点、省略号；导出番茄/起点格式时也会自动规范
- 全书投稿检查：空章、字数不够、没有标题、标点不规范、残留的 AI 回复语、敏感词

**模型**：所有 OpenAI 兼容接口（DeepSeek、Kimi、通义千问、智谱、豆包、硅基流动、OpenRouter、OpenAI、Gemini、本机 Ollama、本机 sub2api 等，内置预设）。写作和分析可以用不同的模型，分析任务可以用便宜的。支持推理模型（自动过滤思考过程）。

**导入导出与迁移**
- 导出：番茄投稿 TXT（第1章）、起点投稿 TXT（第一章）、普通 TXT、Markdown、EPUB；一键复制当前章的投稿格式
- 导入旧稿：txt（自动识别 UTF-8 / GBK / UTF-16）、docx、epub，按“第X章”“第X卷”自动拆章分卷
- 酒馆迁移：导入角色卡（PNG / JSON，V1/V2/V3）和世界书到设定库；保留角色对话，用来试人物性格和台词

**统计**：总字数、已发布和存稿、近 30 天码字、全书张力曲线、各项 AI 调用次数和 token 用量、按模型单价估算的费用，以及每章采纳的 AI 字数。

**AI 使用声明**：在「统计」里点「生成 AI 使用声明」，把 AI 调用按用途（灵感与设定、大纲与规划、校对与润色、正文生成、分析与检查等）汇总成一段可以直接贴到平台的说明，列出正文里有 AI 文字的章节和占比（超过 10% 的标黄）；「导出创作过程记录」导出大纲、各章创建和修改时间、历史版本、每天码字和 AI 使用情况（Markdown）。

**数据备份**：每天自动给数据库存一份快照（放在数据目录的 `backups` 里，默认保留 14 份），可以另外同步一份到网盘文件夹；设置里能立即备份、还原（还原前会再存一份当前数据）和删除。

## 快速开始

### 桌面版（Windows）

双击项目根目录的 `AI小说工坊.exe`。程序在自己的窗口里打开，不用浏览器，也没有命令行窗口，不需要装 Rust。

- 数据放在 exe 旁边的 `data` 目录，放在项目根目录时和浏览器版是同一份。那里不能写（比如放进 Program Files）时改用 `%APPDATA%\ai-novel\data`，也可以用环境变量 `AI_NOVEL_DATA` 指定
- 只有这一个文件，前端和数据库都在里面；拷到别的电脑或 U 盘上也能直接用，第一次运行会在旁边建 `data` 目录
- 只能开一个，再双击会提示已经打开了；关窗口时会先保存正在写的内容
- 窗口大小、位置和是否最大化会记住，下次按原样打开
- 导出的文件保存到「下载」文件夹，保存后会提示路径
- 可以和浏览器版同时开，数据是同一份，但别在两边同时改同一章；主题等界面偏好两边分开保存
- 需要 WebView2 运行时，Windows 10/11 一般自带；缺少时会改用浏览器打开，并提示下载地址
- 改了代码后双击 `打包桌面版.bat` 重新生成 exe（需要 Rust，见下面「浏览器版」）
- 出问题先看 `data\ai-novel.log`；设置环境变量 `AI_NOVEL_DEVTOOLS_PORT=9222` 再启动，可以在 Edge 里打开 `edge://inspect` 调试页面

### 手机版

手机和电脑装上 Tailscale、登录同一个账号，手机浏览器打开电脑的 Tailscale 地址就能用（这台电脑是 `http://pc-20260707ntys.taile4cfb7.ts.net/`），作品和设置跟电脑上是同一份。

- 电脑上跑着一个不带窗口的后台服务：`AI小说工坊.exe --serve`（端口 18688），开机自动运行，靠的是启动文件夹里的「AI小说工坊（手机访问）」快捷方式。它只监听本机，由 `tailscale serve --bg --http 80 http://127.0.0.1:18688` 转给自己账号下的设备，局域网和公网都访问不到
- 手机上的用法：顶栏「目录」「助手」从两边滑出章节列表和 AI 面板，其余功能在「⋯」里；正文底部「✦ 续写一句」等于电脑上的 Ctrl+Enter，灰字出来后点「采纳」；「⋯ → 阅读」整屏看正文、翻章
- 浏览器菜单里「添加到主屏幕」可以放个图标。想像 App 一样全屏打开：在 Tailscale 管理后台的 DNS 页面打开 HTTPS Certificates，再运行 `tailscale serve --bg --https 443 http://127.0.0.1:18688`，改用 `https://` 开头的同一个地址
- 打不开时：确认手机上 Tailscale 是连接状态、设置里「使用 Tailscale DNS」开着，电脑开机且没有睡眠
- 改代码后照常双击 `打包桌面版.bat`，它会先停掉后台服务、换好 exe 再启动
- 不想要了：删掉启动文件夹里的快捷方式，运行 `tailscale serve --http=80 off`，在任务管理器里结束 `AI小说工坊.exe`
- 要从公网访问（比如另开一条 Cloudflare 隧道），一定加访问密码：`AI小说工坊.exe --serve --password 你的密码`

### 浏览器版

需要最新稳定版 Rust（开发时用的是 1.97）；Windows 上还需要 VS Build Tools，用来编译内置的 SQLite。

```powershell
cd E:\工具包\ai-novel
cargo run --release
```

Windows 下也可以直接双击 `启动.bat`。第一次会编译几分钟，之后会自动打开浏览器访问 http://127.0.0.1:8686 。

1. 右上角「设置」→ 选一个接口预设 → 填 API Key → 「测试连接」，在「模型分工」里填写作模型和分析模型 → 保存
2. 书架上点「开新书」，或者「导入旧稿续写」

命令行参数（也可以用环境变量）：

| 参数 | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--host` | `AI_NOVEL_HOST` | `127.0.0.1` | 监听地址，局域网访问用 `0.0.0.0` |
| `--port` | `AI_NOVEL_PORT` | `8686` | 端口 |
| `--data-dir` | `AI_NOVEL_DATA` | `./data` | 数据目录（SQLite 数据库） |
| `--password` | `AI_NOVEL_PASSWORD` | 无 | 访问密码，浏览器会弹出登录框，用户名随意 |
| `--no-browser` | `AI_NOVEL_NO_BROWSER` | 否 | 启动时不自动打开浏览器 |

如果要在局域网里访问，一定要设置密码：设置页里存着你的 API Key。

### Docker

```powershell
docker compose up -d --build
```

数据保存在 `./data`。容器里访问宿主机上的本地模型（Ollama、sub2api）时，接口地址要写 `http://host.docker.internal:端口/v1`，不能写 `127.0.0.1`。

## 推荐的写作流程

1. 每章先写几句章纲：这章发生什么、冲突是什么、结尾留什么钩子（也可以用「AI 规划后续章纲」一次规划十章）
2. 「写整章」出初稿，或者自己写开头再「续写」
3. 自己改：不满意的段落选中后改写、扩写、润色
4. 「检查」：先跑免费的文字质量检查，再做设定一致性检查
5. 「记忆 → 定稿本章」：核对 AI 找出的人物状态变化和伏笔，写回设定库
6. 文风库：平时看到喜欢的段落就收藏进来；攒了几篇范文、也改过一些 AI 文字后，到「文风库 → 文风指南」点「AI 提炼」更新指南，之后 AI 写出来会越来越像你

导入的旧稿建议把最近几章都定稿一遍，让设定库和前情摘要先建立起来。

## 关于平台规则

番茄小说要求作者如实勾选 AI 使用情况，并且在严查“AI 粗制滥造”（复述剧情、提纲式写文、句式重复、水文）；起点反对用 AI 替代真人完成核心内容。《人工智能生成合成内容标识办法》自 2025 年 9 月起施行，要求发布 AI 生成内容时主动声明。

2026 年 8 月起，起点对正文 AI 生成占比超过 10% 的作品撤榜、取消推荐（少量润色纠错、只用 AI 查资料不算）。

这个工具是按“作者主导、AI 辅助”设计的：写作提示词和本地质量检查针对的是上面那些低质特征，目的是让文字本身更好；工具里没有、也不会加入规避平台 AI 检测的功能。「统计」页记录了每次 AI 调用和每章采纳的 AI 字数，「生成 AI 使用声明」可以据此生成如实的声明，「导出创作过程记录」保留创作留痕。具体规则以各平台最新的作者协议为准。

## 开发

```
src/
  main.rs       启动入口、命令行参数
  bin/desktop.rs 桌面版：WebView2 窗口、单实例、记住窗口位置、关窗前保存；--serve 给手机用的后台服务
  lib.rs        路由、静态资源内嵌、访问密码
  api.rs        作品/卷/章节/版本/设定/伏笔/统计接口，定稿写回
  ai.rs         AI 任务：组装上下文和提示词，流式（SSE）和 JSON 两种返回
  llm.rs        OpenAI 兼容客户端：流式解析、思考过程过滤、JSON 提取
  memory.rs     长篇记忆：上下文组装、设定匹配、状态时间轴、BM25 检索、分层摘要
  prompts.rs    提示词模板（默认版本；作者可在界面里覆盖）
  continuity.rs 本地连续性体检
  library.rs    内置题材模板和写作手册
  lint.rs       本地文字质量检查、跨章重复检测
  export.rs     TXT / Markdown / EPUB 导出，投稿检查
  sensitive.rs  本地敏感词库和引流广告识别
  backup.rs     数据库自动备份、还原、同步文件夹
  declare.rs    AI 使用声明、创作过程记录
  importer.rs   TXT / DOCX / EPUB 导入，酒馆角色卡和世界书解析
  text.rs       字数统计、中文分词、章节拆分、中文数字
  db.rs         SQLite 存储（自动迁移）
  models.rs     数据结构和设置
web/            前端（原生 HTML/CSS/JS，无需 Node 构建，编译时内嵌进二进制）；manifest、sw.js、icons/ 用于手机「添加到主屏幕」
tests/api.rs    端到端测试：启动应用和模拟模型，走完整写作流程
examples/mock_openai.rs  模拟的 OpenAI 兼容接口，用于联调界面
build.rs        Windows 下给 exe 加图标和版本信息
assets/         程序图标
```

cargo test                                  # 单元测试 + 端到端测试

$env:AI_NOVEL_LIVE_KEY = "sk-..."   # 可选：AI_NOVEL_LIVE_BASE、AI_NOVEL_LIVE_WRITER、AI_NOVEL_LIVE_ANALYST
