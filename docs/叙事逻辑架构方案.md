# 叙事逻辑架构方案：信息投放与知识边界

起因：作者反馈「第一章就给读者讲了很多高大上的内容，老书虫觉得不对劲，有些东西应该是中后期才出现的」。这不是某一章写得不好，是应用里没有「谁在第几章知道什么」这个概念。本方案把它当成架构问题来改，并参考了同类产品、开源项目、论文和网文写作经验（见第三节和第十节）。

## 一、问题与证据

**证据 1：写第 1 章时，模型拿到了全书底牌。** 对《大梦长生》第 1 章调用「查看提示词」（write_chapter），提示词共 11407 字，【世界观】和【总纲】是整段塞进去的。里面出现的后期内容：

| 词 | 次数 | 应该出现在 |
| --- | --- | --- |
| 伪神 | 8 | 中后期（真相层） |
| 逆命司 | 8 | 第一卷只是通缉榜上的反贼，「预言」「破局钥匙」是第四卷 |
| 三十三重 / 天元天轨 | 3 / 2 | 天地锁链的真相，后期 |
| 灵台 / 洞虚 / 天人 / 斩道 / 极道神境 | 3 / 2 / 1 / 1 / 2 | 第一卷只到开脉境 |
| 归墟神座、九霄天轨 | 各 1 | 第三卷以后 |
| 姜沉雪（逆命司第七席） | 1 | 身份是第四卷的反转 |
| 执秤真皇 | 1 | 全书结局 |

模型手里拿着这些写开篇，自然会往里塞，读者读到的就是「高大上」。TimeChara 的实验也说明了这一点：把不分时间的资料一股脑给模型，泄露未来信息的情况最严重（见第三节）。

**证据 2：正文里出现了视角人物不可能知道的东西。** 第 1 章写太虚梦潮，用了「神魔尸骸、仙殿、规则锁链、诸天万界」；禁物面板一上来就是「诸天禁物」「位阶：界外遗物」，等于第一章就把分级体系摆了出来。一个矿奴第一次做这种梦，不可能知道这些东西叫什么。按网文写作的经验，第一章只该放「当场必懂」的设定，新名词最多一到三个，「金手指说明书」「等级大全」都在禁止之列。

**证据 3：前后矛盾没有任何检查能发现。** 原稿 10 章里：境界第 2、5 章已到五重，第 7 章又写「连破四、五、六重」，第 10 章写「从三重连破到七重」；砝码按设定只压一个小境界，却把赵陵从六重压到三重；王奎的令牌第 3 章塞进了阵里、第 9 章又出现在陈渊身上；毒灵髓第 5 章「耗竭无存」、第 6 章又拿去当铺。这些都是人工通读才发现的。

## 二、根因（对照现有代码）

上下文由 `memory::compose()` 组装，写章类任务（continue / write_chapter / beats）开启 `include_world` 和 `include_outline`。泄露通道如下：

| 通道 | 现状 | 后果 |
| --- | --- | --- |
| 世界观 | 整段塞入（预算 12%） | 第 1 章看到全部底牌 |
| 总纲 | 整段塞入（预算 10%），含后几卷和结局 | 写开篇就知道结局，倾向提前铺垫、点破 |
| 设定描述 | 条目一出场，description 和 immutable 原样下发 | 姜沉雪的真实身份、未来剧情跟着进提示词 |
| 无快照的设定 | `state_at()` 回落到最新状态 | 回改前面的章节时看到后面的状态 |
| 人物关系 | `relation_lines()` 不看 `since_chapter_id` | 后来才建立的关系提前出现 |
| 未回收伏笔 | 只看 status，不看埋设章节 | 回改前文时看到后面才埋的伏笔 |
| 开篇要求 | `golden_hint` 只说「尽早亮出金手指」 | 没有「世界观收着写」的约束 |

校验侧的缺口：
- 没有「读者知道什么」的数据，`task.check` 第 4 条问「人物是否知道了他还不知道的事」，模型只能凭感觉答。
- `continuity.rs` 只查伏笔、人物出场、死人出场、摘要、张力，不查境界走向、物品去向、设定超前、新名词密度。

已有的好基础：设定状态按章节存快照（`entry_states`，start/end 两相），`state_at()` 已经只看本章之前的快照；人物状态有结构化字段，含 `knows / unaware`；定稿流程会提取设定变化并入账（`task.extract` → `apply_updates`）。这次改造沿着这条路往前走。

## 三、别人是怎么解决的

| 来源 | 做法 | 我们采纳什么 |
| --- | --- | --- |
| Novelcrafter（商业） | Codex「Progressions」：设定的补充或替换挂在稿子的某个位置，AI 只有写到这里及以后才看得见；细节可设「永不发给 AI」；官方指南直说「别在描述里写剧透，AI 不管写到哪都会读完整描述」 | 设定进展按章节生效；作者底牌永不下发；提示词预览可核对 |
| 马良写作（国内产品） | 「设定可见性」：每条设定、角色、悬念可「对 AI 隐藏」或「按卷渐进开放」，可批量设置；原则是「可见性是红线，上下文装配是配额」 | 可见性先于预算过滤，任何装配设置都绕不过去；按卷批量设置 |
| webnovel-writer（开源，GPL，只借鉴思路） | 每章有「合同」：目标、时间锚点、必写节点、**禁区**、章末未决问题；伏笔、悬念、感情线分账，各有生命周期（埋下→推进→回收、设下→揭晓）；审稿只报有原文证据的问题，且不得在问题里暴露未发生的剧情；派生报表「谁还不知道主角底牌」用来蓄积打脸 | 章节合同里的禁区；秘密单独建账；审校不泄底；底牌知情表 |
| webnovel-handbook（开源，MIT） | 设定分三层：当场必懂、近期会用、后台暂存；冰山原则「作者知道十成，读者先看一成」；第一章新名词最多一到三个；第 3～6 章反复验证核心规则，第 10 章前至少回收一次设定；信息差分作者、主角、读者、对手四方；每 3～8 章给一次信息进度；关键线索隔十章以上再揭示，揭示前要唤醒 | 三层投放、新名词密度、开篇里程碑、信息进度和记忆温度检查、四方知情；写作规则按 MIT 许可改编 |
| QMAI、novel-studio（开源） | 角色认知系统（知道 / 不知道）；人物只知道自己的档案和已知事实，由「世界裁判」防止人物提前知道秘密 | 角色知识带获知来源 |
| TimeChara（ACL 2024） | 角色扮演模型普遍会泄露「未来」信息，GPT-4o 在这类题上只有 46%；不分时间地给资料效果最差；按时间截断检索、把判断拆成「这件事是不是在未来」「这个人当时在不在场」两步能明显减少泄露；推理型模型明显更好 | 所有资料按章节截断；逻辑审校拆成时间、在场、获知来源三问；审校用更强的模型 |
| FactTrack、DOME（NAACL 2025）、ConWriter（2026） | 把事件拆成原子事实，每条事实带「从第几章到第几章有效」，新事实和有效事实冲突就报警；逐场景写作，每个场景当成一次可检查的状态转移，提交前校验，只修出问题的句子 | 境界、物品先做规则检查，后期升级为带有效区间的原子事实；定稿前校验，修订模式只改问题句 |
| StoRM（EMNLP 2022）、悬念生成（2024） | 显式的「读者模型」记录读者相信什么；读者知道而人物不知道的危险产生悬念，人物知道而读者不知道的事揭开时产生惊奇 | 读者层和角色层分开存，规划时可利用信息差 |
| 叙事学（Bordwell、Sternberg） | 故事（真相、时间顺序）和叙述（选择、顺序、隐藏、揭示）是两回事；缺口可以「亮出来」（好奇）或「藏起来」（惊奇），已知威胁延后结果是悬念 | 每个秘密标注缺口类型，决定前期能不能让读者察觉 |
| 网文写作经验（网文666 等） | 设定拆碎、跟着剧情露；三步放：埋种子（顺嘴一提不解释）→给线索（主角撞上一角）→揭真相；「删掉这段，剧情还通不通」 | 揭示分三步；纯设定段落检查 |

结论：同类产品已经在用「按进度开放」的思路，研究和写作经验都指向同一件事：资料按时间截断，信息分层分批放，事实入账后再校验。我们的设计在这些做法上再往前走一步，把读者层、角色层和揭示计划连成一个闭环。

## 四、设计原则

1. **作者全知，读者和角色逐章知道。** 分三层：作者层（真相、底牌）、读者层（截至第 N 章已经揭示的）、角色层（每个角色截至第 N 章知道的，包括误会）。同一个秘密要能说清读者、主角、对手各知道多少。
2. **可见性是红线，装配是配额。** 先按可见性筛掉第 N 章不该看见的资料，再按预算装配。任何装配设置都绕不过可见性。
3. **冰山原则。** 作者层可以写十成，正文先露一成。每章的设定分三层投放：当场必懂（可以写明）、近期会用（只挂钩子、不解释）、后台暂存（不进正文）。
4. **揭示是规划出来的。** 每个秘密有缺口类型和三步计划（埋种子、给线索、揭真相），在规划时定，写作时守，定稿时记。
5. **事实入账，规则先行。** 定稿时登记「本章揭示了什么、谁知道了什么、状态怎么变」；免费的规则检查先跑，模型审校兜底；审校只报有原文证据的问题，修订只改问题句。
6. **不加重作者负担。** 揭示计划一键生成、作者审核；可见性可以按卷批量设；没有计划的书按卷自动推断默认值，行为不比现在差。

## 五、目标架构

```
规划层：揭示计划、章节合同（必写节点、投放清单、禁区）
   ↓
组装层：可见性过滤（红线）→ 按预算装配（配额），附本章投放清单
   ↓
生成层：写作规则 + 投放清单 + 禁区
   ↓
校验层：规则检查（免费、即时）→ 模型逻辑审校（可选）
   ↓
入账层：定稿提取状态变化、揭示进度、角色知识
   ↓（回到规划层）
```

### 5.1 数据模型

**可见性**（加在所有资料上）：
- 设定条目、世界观分节、总纲分节、伏笔、悬念都有可见性：公开 / 对 AI 隐藏（作者备注）/ 从第几章或第几卷起开放。
- 世界观和总纲按标题自动分节（如「第一卷」「金手指规则」），每节默认按所属卷开放，「结局」「核心主线」默认对 AI 隐藏，作者可改。

**设定进展**（参考 Novelcrafter Progressions）：设定的补充或替换挂在某一章，写到这一章及以后才下发。用来放「第四卷揭示姜沉雪是逆命司第七席」这类信息，描述本身只写读者一开始就能知道的部分。实现上扩展现有 `entry_states`，增加补充 / 替换两种类型。

**秘密台账 reveals**（字段参考 webnovel-handbook 的真相台账）：

| 字段 | 说明 |
| --- | --- |
| title | 短标题，如「天轨是伪神铸造的锁链」「境界体系（灵台以上）」「姜沉雪的身份」 |
| truth | 最终真相（作者层，只给规划和审校用） |
| misread | 前期读者最容易相信的表面解释（可空） |
| gap | 缺口类型：好奇（读者知道有谜，可以亮出缺口）/ 惊奇（不能让读者察觉，只留公平线索）/ 悬念（读者知道威胁，结果延后） |
| terms | 泄露词，命中就算点破；可写例外，如「天轨护道盟」不算泄露「天轨真相」 |
| entry_ids | 关联的设定条目 |
| seed_at / clue_at / reveal_at | 三步计划：埋种子、给线索、揭真相分别在第几章（可空，按卷默认） |
| payoff | 揭开后改变什么：人物、关系、资源、世界、对手 |

**揭示进度 reveal_events**：某章对某个秘密做了哪一步（种子 / 线索 / 揭开），附原文依据，定稿时写入。读者层就是截至第 N 章的所有揭示进度。

**角色知识 knowledge**：某个角色从第几章起知道某个秘密，获知来源（亲历 / 被告知 / 推断），是真相还是误会。由此派生「底牌知情表」：谁还不知道主角的真实实力和底牌。

现有表的调整：
- `entries` 增加 `intro_chapter_id`（首次登场，定稿时自动填）和 `secret`（作者底牌，永不下发）；`description` 只放读者可以知道的设定。
- `relations.since_chapter_id`、`threads.planted_chapter_id` 已有，组装时开始用。
- `books` 增加 `public_world`（读者层的世界说明，开篇只写主角碰得到的部分，随揭示进度扩充）。原有 `worldview`、`outline` 保留为作者层设定集。

### 5.2 组装层：先过红线，再分配额

第一步，可见性过滤：第 N 章看不见的资料一律剔除，包括还没开放的世界观分节和总纲分节、对 AI 隐藏的条目和细节、第 N 章之后才生效的设定进展、之后才建立的关系、之后才埋的伏笔。

第二步，按预算装配，段落如下：

| 段落 | 内容 |
| --- | --- |
| 作品信息 | 书名、题材、一句话梗概、简介 |
| 世界（读者已知） | `public_world` + 已揭开秘密的读者说法 |
| 本卷卷纲 | 只给当前卷 |
| 前情提要 | 本章之前的摘要 |
| 相关设定（必须遵守） | 已登场或本章计划登场的条目：公开描述 + 已生效的设定进展 + `state_at()`；不含 `secret` |
| 人物关系、未回收伏笔 | 按章节过滤后 |
| 视角人物知道 / 不知道 | 来自角色知识；明确列出「不知道」比只列「知道」更能防止泄露 |
| 相关前文、上一章结尾 | 本章之前 |
| 本章投放清单 | 当场必懂（可以写明）、近期会用（只挂钩子：让人物撞见异常、听到禁忌，不解释原理）、本章要埋的种子和给的线索 |
| 禁区 | 还没到开放章节的秘密：短标题 + 泄露词，不附真相 |

规划类任务（总纲、卷纲、章纲规划、节拍）看作者层，但同时拿到揭示计划，按计划安排揭示。

### 5.3 生成层

写作系统提示和内置技能「网文去AI味」增加「信息投放」规则（改编自 webnovel-handbook，MIT）：
- 只写读者此刻该知道的；禁区里的词一个都不要出现，也不要用旁白暗示。
- 设定通过行动、冲突、后果、选择、物件、传闻、异常带出来，不写纯设定段落，不让人物「如你所知」地背常识。
- 第一章只放当场必懂的设定，新名词最多一到三个，每个都要绑在动作或后果上；不写等级大全、地图介绍、组织图谱、金手指说明书。
- 金手指先写能干什么、要付什么代价，来历和分级体系留到后面。
- 紧贴视角人物：旁白不替他说出他不知道的名字和来历，不提前确认幕后真相；主角向读者藏底牌时，前文必须有公平线索。
- 「惊奇」类秘密在揭开前不许引人注意，「好奇」类可以让读者察觉有谜但不给答案。

第 1 章的开篇要求同步修改：世界观只给主角此刻碰得到的部分。

### 5.4 校验层

**规则检查**（新增 `logic.rs`，接入连续性体检和章节检测，不调用模型）：

| 检查 | 级别 | 规则 |
| --- | --- | --- |
| 设定超前 | 严重 | 第 N 章出现了还没开放的秘密的泄露词，或还没开放的设定条目 |
| 提前点破 | 警告 | 在埋种子到揭开之间出现了泄露词，提示作者确认是线索还是点破 |
| 新名词密度 | 警告 | 本章首次出现的专有名词（设定名、书名号、境界等）超过阈值，第 1 章超过 3 个就报 |
| 纯设定段落 | 提示 | 连续三段以上没有动作、对话，设定名词密集 |
| 境界走向 | 警告 | 按人物 power 字段逐章解析「境界 + 层数」，出现倒退（且无受伤、压制、跌落字样）或同一层被重复突破 |
| 物品去向 | 警告 | 物品状态已是耗尽 / 损毁 / 交出 / 被夺，之后又被使用或持有 |
| 信息进度 | 提示 | 某个开着的秘密连续 8 章以上没有任何种子、线索或揭开 |
| 记忆温度 | 提示 | 秘密在第 N 章计划揭开，但最近一次线索在 10 章以前，揭开前需要唤醒 |
| 开篇里程碑 | 提示 | 第 10 章前没有任何设定回收（前文出现的规则、物品、禁忌变成爽点或危机解法） |

前面列的四处原稿矛盾，境界走向和物品去向两项都能自动报出来。

**模型逻辑审校**（新任务 `logic_check`，分析模型，输出 JSON）：输入本章正文、读者层（截至上一章）、本章投放清单和禁区、视角人物知识、相关设定的状态快照。参考 TimeChara 的做法，每条可疑内容按三问判断：这件事对第 N 章来说是不是在未来；说出或用到它的人当时在不在场；他有没有获知来源。检查五类：超前揭示、角色越知、因果缺口（行动依赖还没交代的信息或资源）、状态矛盾、视角越权。每条问题必须引用原文、附最小改法，改法里不得写入还没发生的剧情。审校用设置里最强的分析模型。接入定稿流程：规则检查有严重问题时先提示，模型审校可选。

### 5.5 入账层

`task.extract` 的输出加三项，`apply_updates` 对应入账：
- `reveals`：本章对哪些秘密埋了种子、给了线索或揭开了，附原文依据；发现计划外的新秘密时作为新条目草稿。
- `knowledge`：哪个人物知道了什么、怎么知道的、是不是误会。
- `intro`：首次登场的设定条目。

和现在一样，提取结果先给作者确认再入库。

### 5.6 规划层

- **生成揭示计划**（新任务 `reveal_plan`）：读世界观、总纲、卷纲和已写章节摘要，按「倒推」做法拆出秘密：先写真相，再定表面误读、缺口类型、三步计划和泄露词；同时把世界观和总纲分节并给出默认可见性；标出已写章节里已经揭开的部分。结果作为草稿交给作者审核。
- **章节合同**：章纲规划和节拍生成时，按揭示计划自动带出本章的投放清单、要埋的种子和线索、禁区；前 10 章加信息预算（新名词、新概念的数量上限）。
- **开篇里程碑**：规划前 30 章时检查第 1 章只放当场必懂、第 3～6 章验证核心规则、第 10 章前有设定回收、第 30 章前设定引擎成型。
- **卷纲生成**：按揭示计划安排每卷的揭开点。

### 5.7 界面

- **信息节奏面板**（书级）：按卷列出秘密，每条一根时间条（种子 → 线索 → 揭开），实际进度来自揭示进度，可以直接拖动计划章节；「一键生成揭示计划」入口；底牌知情表。
- **可见性**：设定、世界观分节、总纲分节都能单独或批量设置「对 AI 隐藏 / 第几卷起开放」。
- **章节侧栏「本章合同」卡片**：读者已知多少条、本章投放清单、禁区；逻辑检查结果可以点击跳到原文，在修订模式里只改问题句。
- **设定编辑**：公开设定、设定进展（挂在第几章）、作者底牌、首次登场章节分开。
- **查看提示词**：能看到投放清单和禁区。

**第四期完成情况（2026-10-06）**
- 实现：章纲规划拿到「这几章的信息投放」（`memory::schedule_lines`：按揭示计划每章要埋的种子、要给的线索、要揭开的秘密，以及这几章都不能写破的秘密和泄露词），覆盖前 30 章时再给开篇要求（`prompts::opening_plan`：第 1～10 章新名词预算、第 3～6 章验证核心规则、第 10 章前设定回收、第 30 章前设定引擎成型）；每章多出合同 `reveals`、`hook`、`new_terms`，生成后 `api::mark_outline_contract` 逐章核对提前写出的泄露词、漏排的投放和前 10 章超预算的新名词，采纳时章末悬念写进章纲。卷纲生成带上揭示计划。写第 2～10 章时给新名词预算，和规则检查的上限一致。规则检查新增开篇里程碑（前 10 章没回收过伏笔）和秘密标题带出设定。侧栏记忆页加「本章合同」卡片（`GET /chapters/{id}/contract`）。
- 和上面计划不同的地方：
  - 章节合同不单独存：投放清单和禁区写正文时照旧按揭示计划现算，作者拖动了计划不会和章纲对不上；章纲里只多写一行「章末：」，必写节点就是章纲本身。合同里的 `reveals`、`new_terms` 只用来在采纳前核对。
  - 新名词预算沿用规则检查的上限：第 1 章 3 个，第 2～3 章 5 个，第 4～10 章 7 个。
  - 开篇里程碑只有「第 10 章前设定回收」做成了规则（拿伏笔回收当依据），其余三条只进规划提示词：「验证核心规则」「设定引擎成型」靠规则判断不了。
  - 多了一条「秘密标题带出设定」：验收里唯一一处越界，是秘密「天元天轨与天地浊灵气的来历」的标题带着第 4 卷才开放的设定名，标题进了第 3 章的投放清单，模型就写了出来。
  - 境界、物品升级为带有效区间的原子事实没有做，见下面「没做到的」。
- 验收结果（在书库副本上用真实模型做，正式书库没动）：新建两本测试书，都复制《大梦长生》的作品设定、卷纲、设定库（不带后面章节的人物状态）、设定进展和 12 条秘密；一本放第 1～3 章最早的原稿（叙事逻辑改造前的 AI 初稿），一本用新流程重新规划前 3 章章纲、逐章生成节拍和正文（写作模型 gemini-3.8-flash）。
  - 章纲完全按计划排了投放：第 1 章埋「天寿税与断命劫的真正去向」「万界太虚梦潮的尽头渊源」，第 3 章埋「天平禁物的完整形态与使用代价」「天元天轨与天地浊灵气的来历」，和揭示计划的第 1、3 章安排一致；核对没有警告，第 1 章新名词 3 个在预算内。
  - 信息越界从 4 处降到 1 处。原稿：第 1 章写出「伪神」（第 4 卷才开放）、用「伪神收割印记」点破天寿税的真相；第 3 章写出「界外遗物」、把禁物分级面板摆了出来。新流程：只有第 3 章写出「天元天轨」，规则检查当场报出，原因见上。
  - 后期词（不算第一卷允许写的「灵台」）从 4 次降到 1 次；第 1 章新名词从 3 个（含「伪神」）降到 2 个；规则检查的问题从 2 条降到 1 条。
  - 模型审校的问题总数两边都是 4 条，但原稿里有 2 条是超前揭示；新流程的 4 条全是和章纲、设定细节对不上的状态矛盾或因果缺口（赵崇山的台词把「下个月核验」写成「三天后」、王奎的武器写成矿镐等），没有信息越界。
  - 冷读者通读第 1 章：两版都说会点下一章，都觉得太虚梦潮那段太密；原稿那段被点名「一口气塞了太虚梦潮、伪神收割印记、浊灵气」，新流程只说画面大而抽象。新流程第 1 章只写了 1604 字（目标 2500），模型偏短。
  - 114 个单元测试、13 个接口测试、2 个真实书稿测试通过。
- 境界、物品的有效区间（同日补上）：`logic::facts` 从定稿按章入账的快照推出「某人第几章起是什么境界、到第几章被取代」「某件物品第几章起已经没了」，没变化的快照不切区间；写某一章时组装层加「境界和物品（截至上一章，按章入账）」，只给出场人物和物品在本章之前已经生效的（本章里才变的，写本章时还没变）；本章合同卡片也显示，`GET /books/{id}/facts` 列出全书。没有新加表和提取步骤：快照本来就是按章、带原文入账的，区间直接从快照推，作者改快照区间跟着变；冲突检查沿用第一期的境界走向、物品去向规则。
- 没做到的：正式书库的秘密「天元天轨与天地浊灵气的来历」要改标题（体检会提醒）；开篇里程碑的另外三条没有规则检查；事实只覆盖境界和物品，位置、伤势、关系还没有区间。

**第四期遗留（2026-10-07 补上）**
- 秘密标题已改成「天轨与浊灵气的来历」。
- 位置、身体、关系的有效区间：位置和身体照境界的做法从章末快照推，没写这一项或写着「无变化」的快照按没变算；写某一章时出场人物合成一行，带「第N章起」，本章里才变的写本章时还是旧的；关系用关系表的起止章节列进 `GET /books/{id}/facts`，以前就已结束、没记结束章节的标出来。正式书库 8 条以前就已结束的关系按各章摘要补了结束章节（王奎第 2 章死，赵陵和黑虎巡查队第 4 章，赵黑虎、徐平安第 8 章），改前存了备份「20261007-194345-补关系结束章节前」。
- 开篇里程碑：新名词预算本来就是规则检查；「验证核心规则」「设定引擎成型」规则判断不了，做成检查页的「开篇里程碑核对（AI）」，按第 1 章到当前章的摘要逐条判断、给证据和补法。《大梦长生》前 10 章三条都判做到了。
- 还没做：现有秘密都没关联陈渊，知情表里没有「底牌」行，要作者定拆哪几条；「替换这句」还没接进逐句对比的修订界面。

每一期都配单元测试、接口测试，并用真实模型做前后对比（做法同去 AI 味的评测：多次采样、统计、通读）。

## 八、风险与取舍

- **作者要多维护一份计划。** 一键生成、按卷批量设置、按卷默认值；没有计划的书退回第一期的规则，不会比现在差。
- **收得太紧会写得干。** 悬念本身就是钩子，种子和线索允许提前出现；禁的是「点破」「大词」和「说明书」，不禁神秘感。
- **泄露词会误报。** 例如「天轨护道盟」含「天轨」。泄露词支持词组和例外；检查结果都附原文，由作者判断。
- **提取会出错。** 揭示进度和角色知识跟现在的设定提取一样，先作为草稿给作者确认。
- **改动面大。** 按期交付，每期独立可用；数据库只加表加列，旧数据不动。
