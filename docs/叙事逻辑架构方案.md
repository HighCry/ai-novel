# 叙事逻辑架构方案：信息节奏与知识边界

起因：作者反馈「第一章就给读者讲了很多高大上的内容，老书虫觉得不对劲，有些东西应该是中后期才出现的」。这不是某一章写得不好，是系统里没有「谁在第几章知道什么」这个概念。本方案把它当成架构问题来改。

## 一、问题与证据

**证据 1：写第 1 章时，模型拿到了全书底牌。** 对《大梦长生》第 1 章调用「查看提示词」（write_chapter），提示词共 11407 字，其中【世界观】和【总纲】是整段塞进去的。里面出现的后期内容：

| 词 | 次数 | 应该出现在 |
| --- | --- | --- |
| 伪神 | 8 | 中后期（真相层） |
| 逆命司 | 8 | 第一卷只是通缉榜上的反贼，「预言」「破局钥匙」是第四卷 |
| 三十三重 / 天元天轨 | 3 / 2 | 天地锁链的真相，后期 |
| 灵台 / 洞虚 / 天人 / 斩道 / 极道神境 | 3 / 2 / 1 / 1 / 2 | 第一卷只到开脉境 |
| 归墟神座、九霄天轨 | 各 1 | 第三卷以后 |
| 姜沉雪（逆命司第七席） | 1 | 身份是第四卷的反转 |
| 执秤真皇 | 1 | 全书结局 |

模型手里拿着这些写开篇，自然会往里塞，读者读到的就是「高大上」。

**证据 2：正文里出现了视角人物不可能知道的东西。** 第 1 章写太虚梦潮，用了「神魔尸骸、仙殿、规则锁链、诸天万界」；禁物面板一上来就是「诸天禁物」「位阶：界外遗物」，等于第一章就把分级体系摆了出来。一个矿奴第一次做这种梦，不可能知道这些东西叫什么。

**证据 3：前后矛盾没有任何检查能发现。** 原稿 10 章里：境界第 2、5 章已到五重，第 7 章又写「连破四、五、六重」，第 10 章写「从三重连破到七重」；砝码按设定只压一个小境界，却把赵陵从六重压到三重；王奎的令牌第 3 章塞进了阵里、第 9 章又出现在陈渊身上；毒灵髓第 5 章「耗竭无存」、第 6 章又拿去当铺。这些都是人工通读才发现的。

## 二、根因（对照现有代码）

上下文由 `memory::compose()` 组装，写章类任务（continue / write_chapter / beats）开启 `include_world` 和 `include_outline`。泄露通道如下：

| 通道 | 现状 | 后果 |
| --- | --- | --- |
| 世界观 | 整段塞入（预算 12%） | 第 1 章看到全部底牌 |
| 总纲 | 整段塞入（预算 10%），含后几卷和结局 | 写开篇就知道结局，倾向提前铺垫、点破 |
| 设定描述 | 条目一出场，description 和 immutable 原样下发 | 姜沉雪的真实身份、未来剧情跟着进提示词 |
| 无快照的设定 | `state_at()` 回落到最新状态 | 回改前面的章节时看到后面的状态 |
| 人物关系 | `relation_lines()` 不看 `since_chapter_id` | 后来才建立的关系提前出现 |
| 未回收伏笔 | 只看 status，不看埋设章节 | 回改前文时看到后面才埋的伏笔 |
| 开篇要求 | `golden_hint` 只说「尽早亮出金手指」 | 没有「世界观收着写」的约束 |

校验侧的缺口：
- 没有「读者知道什么」的数据，`task.check` 第 4 条问「人物是否知道了他还不知道的事」，模型只能凭感觉答。
- `continuity.rs` 只查伏笔、人物出场、死人出场、摘要、张力，不查境界走向、物品去向、设定超前。

已有的好基础：设定状态按章节存快照（`entry_states`，start/end 两相），`state_at()` 已经只看本章之前的快照；人物状态有结构化字段，含 `knows / unaware`；定稿流程会提取设定变化并入账（`task.extract` → `apply_updates`）。这次改造沿着这条路往前走。

## 三、设计原则

1. **作者全知，读者和角色逐章知道。** 分三层：作者层（真相、底牌）、读者层（截至第 N 章已经揭示的）、角色层（每个角色截至第 N 章知道的，包括误会）。
2. **写第 N 章只给第 N 章该有的。** 模型拿到的是读者层、本章计划揭示或暗示的内容、视角人物知道的事。作者层只以「禁写约束」出现，不整段下发。
3. **揭示是规划出来的。** 每个秘密和大概念都有「从第几章起可以暗示」「第几章揭示」，在规划时定，写作时守，定稿时记。
4. **事实入账，规则先行。** 定稿时登记「本章揭示了什么、谁知道了什么、状态怎么变」；免费的规则检查先跑，模型审校兜底。
5. **不加重作者负担。** 揭示计划一键生成、作者审核；没有计划的书按卷自动推断默认值，行为不比现在差。

## 四、目标架构

```
规划层：揭示计划、章节信息预算
   ↓
组装层：按「第 N 章、视角人物」组装上下文，附信息边界
   ↓
生成层：写作规则 + 信息边界
   ↓
校验层：规则检查（免费、即时）→ 模型逻辑审校（可选）
   ↓
入账层：定稿提取状态变化、揭示进度、角色知识
   ↓（回到规划层）
```

### 4.1 数据模型

新增三张表：

**reveals（信息单元）**：一条需要按节奏放出来的信息，可以是世界真相、身份秘密、能力体系、来历、伏笔答案。

| 字段 | 说明 |
| --- | --- |
| title | 短标题，如「天轨是伪神铸造的锁链」「境界体系（灵台以上）」「姜沉雪的身份」 |
| truth | 完整真相（作者层，只给规划和审校用） |
| hint | 可以怎么暗示（给写作用，可空） |
| kind | world / identity / system / origin / foreshadow |
| terms | 泄露词，命中就算点破（如「伪神、归墟神座」）；可写例外，如「天轨护道盟」不算泄露「天轨真相」 |
| entry_ids | 关联的设定条目 |
| hint_from | 从第几章起允许暗示（空 = 按卷默认） |
| reveal_at | 第几章揭示（空 = 未定） |
| volume_id | 计划所在卷 |

**reveal_events（揭示进度）**：某章对某条信息做了什么，定稿时写入。字段：reveal_id、chapter_id、stage（hinted / partial / revealed）、excerpt（原文依据）。读者层就是「截至第 N 章的所有 reveal_events」。

**knowledge（角色知识）**：某个角色从第几章起知道某条信息。字段：entry_id（人物）、reveal_id、chapter_id、source（亲历 / 被告知 / 推断）、belief（真 / 误会）。

现有表的调整：
- `entries` 增加 `intro_chapter_id`（首次登场，定稿时自动填）和 `secret`（作者底牌，不随出场下发）；`description` 只放读者可以知道的设定。
- `relations.since_chapter_id`、`threads.planted_chapter_id` 已有，组装时开始用。
- `books` 增加 `public_world`（读者层的世界说明，开篇时只写主角碰得到的部分，随揭示进度扩充）。原有 `worldview`、`outline` 保留为作者层设定集。

### 4.2 组装层：按第 N 章视角组装

章节级写作任务不再下发原始世界观和总纲。新的段落：

| 段落 | 内容 | 时间规则 |
| --- | --- | --- |
| 作品信息 | 书名、题材、一句话梗概、简介 | 不变 |
| 世界（读者已知） | `public_world` + 已揭示信息单元的读者说法 | 截至上一章 |
| 本卷卷纲 | 当前卷 | 只给本卷 |
| 本章信息计划 | 计划揭示的（可以写明）、计划暗示的（只给线索，不点破） | 本章 |
| 前情提要 | 不变 | 本章之前 |
| 相关设定（必须遵守） | `description` + `state_at()`；不含 `secret` | 只含已登场或本章计划登场的条目；无快照时用初始状态 |
| 人物关系 | | `since_chapter_id` ≤ 本章 |
| 视角人物知道 / 不知道 | 来自 knowledge | 截至上一章 |
| 未回收伏笔 | | 埋设章节在本章之前 |
| 相关前文、上一章结尾 | 不变 | 本章之前 |
| 信息边界（禁写） | 还没到暗示窗口的信息：短标题 + 泄露词，不附真相 | 本章 |

规划类任务（总纲、卷纲、章纲规划、节拍）仍然看作者层，但同时拿到揭示计划，按计划安排揭示。

### 4.3 生成层

- 写作系统提示加一条「信息边界」：只写读者此刻该知道的；信息边界里的词一个都不要出现，也不要用旁白暗示；叙述不替视角人物说出他不知道的名字和来历；新东西第一次出现时，写主角看到的样子，名字留给剧情。
- 内置技能「网文去AI味」的写作规则加「信息节奏」：前期不出现宇宙级的大词；金手指先写能干什么、要付什么代价，来历和分级体系留到后面；用悬念代替解释。
- 第 1 章开篇要求补一句：世界观只给主角此刻碰得到的部分，等级体系和金手指来历留到后面。

### 4.4 校验层

**规则检查**（新增 `logic.rs`，接入连续性体检和章节检测，不调用模型）：

| 检查 | 级别 | 规则 |
| --- | --- | --- |
| 设定超前 | 严重 | 第 N 章出现了 hint_from > N 的信息单元的泄露词 |
| 提前点破 | 警告 | 在暗示窗口内（hint_from ≤ N < reveal_at）出现了泄露词，提示作者确认是暗示还是点破 |
| 条目超前 | 警告 | 提到了 intro 晚于本章、也不在本章计划里的设定条目 |
| 境界走向 | 警告 | 按人物 power 字段逐章解析「境界 + 层数」，出现倒退（且无受伤、压制、跌落字样）或同一层被重复突破 |
| 物品去向 | 警告 | 物品状态已是耗尽 / 损毁 / 交出 / 被夺，之后又被使用或持有 |
| 前期大词密度 | 提示 | 前 10 章「诸天、万界、神明、法则、纪元、本源、位阶、天道」等词超过阈值 |

前面列的四处原稿矛盾，境界走向和物品去向两项都能自动报出来。

**模型逻辑审校**（新任务 `logic_check`，分析模型，输出 JSON）：输入本章正文、读者层（截至上一章）、本章揭示计划、视角人物知识、相关设定的状态快照。检查五类：超前揭示、角色越知、因果缺口（行动依赖还没交代的信息或资源）、状态矛盾、视角越权（旁白说出了视角人物不知道的事）。每条问题必须引用原文，附最小改法。接入定稿流程：规则检查有严重问题时先提示，模型审校可选。

### 4.5 入账层

`task.extract` 的输出加三项，`apply_updates` 对应入账：
- `reveals`：本章暗示 / 部分揭示 / 揭示了哪些信息单元，附原文依据；发现计划外的新秘密时作为新条目草稿。
- `knowledge`：哪个人物知道了什么、怎么知道的、是不是误会。
- `intro`：首次登场的设定条目。

和现在一样，提取结果先给作者确认再入库。

### 4.6 规划层

- **生成揭示计划**（新任务 `reveal_plan`）：读世界观、总纲、卷纲和已写章节的摘要，拆出信息单元，给出泄露词、关联条目、建议的暗示和揭示章节（默认按卷），并标出已写章节里已经揭示过的，作为草稿交给作者审核。
- **章纲规划、节拍**：拿到目标章节的揭示计划，写明「本章揭示 / 暗示」；加信息预算，前 10 章每章新概念不超过两个。
- **卷纲生成**：按揭示计划安排每卷的揭示点。

### 4.7 界面

- **信息节奏面板**（书级）：按卷列出信息单元，每条一根时间条（未放出 → 暗示 → 揭示），实际进度来自 reveal_events，可以直接改暗示和揭示章节；「一键生成揭示计划」入口。
- **章节侧栏「本章信息边界」卡片**：读者已知多少条、本章计划揭示或暗示什么、禁写词；逻辑检查结果可以点击跳到原文。
- **设定编辑**：公开设定、作者底牌、首次登场章节三栏分开。
- **查看提示词**：能看到信息边界这一段。

## 五、在《大梦长生》上的落地

默认揭示计划（按现有总纲推断，作者可调整）：

| 第一卷可以写 | 留到后面 |
| --- | --- |
| 赤炼宗、黑灵矿、浊尘坊市 | 伪神、三十三重天轨的真相 |
| 护道盟：收税的上级，远处的权威 | 归墟神座、九霄天轨 |
| 天寿税：矿上要交的税 | 灵台以上的境界（洞虚、天人、斩道、极道） |
| 炼体境、开脉境；裴少卿是灵台境，只写他有多强 | 太虚梦潮和禁物的来历、禁物分级 |
| 太虚梦潮：只写主角看到的怪潮和漂着的残骸 | 逆命司的预言、「破局钥匙」 |
| 禁物：能干什么、代价 | 姜沉雪的真实身份 |
| 逆命司：通缉榜上的反贼 | 全书结局 |

已写的 10 章：按新规则检查一遍，把超前的内容收回去。例如第 1 章梦潮只写看到了什么、不点破是什么；禁物面板只留名字、作用和代价，去掉「诸天禁物」「界外遗物」的分级字样。

## 六、分期实施与验收

**第一期：止血**
- 组装层：章节级写作不再下发原始世界观和总纲，改为当前卷卷纲 + 读者层世界说明；关系、伏笔、设定登场按章节过滤；无快照的设定用初始状态；`secret` 不下发。
- 书级「禁写清单」（信息单元的简化版：泄露词 + 解锁章节），写作规则和第 1 章开篇要求同步修改。
- 规则检查：设定超前、境界走向、物品去向、前期大词密度。
- 验收：第 1 章提示词预览里不再出现第二节列出的后期词；把原稿 10 章（已存在各章「版本」里）作为回归样本，境界和物品两项矛盾能自动报出；单元测试和接口测试通过。

**第二期：揭示计划**
- reveals、reveal_events 两张表和接口；`reveal_plan` 任务和审核界面；组装层加「读者已知」「本章信息计划」「信息边界」；定稿提取写入揭示进度；信息节奏面板。
- 验收：本书生成揭示计划；任选几章预览提示词，三类信息分得对；定稿后时间条更新。

**第三期：角色知识 + 模型审校**
- knowledge 表；组装层加视角人物知道 / 不知道；`logic_check` 任务接入定稿；侧栏显示检查结果。
- 验收：构造「人物提前知道秘密」「旁白说出人物不知道的名字」的样章，审校能指出并引用原文。

**第四期：规划联动**
- 章纲规划、节拍、卷纲生成按揭示计划和信息预算出稿。
- 验收：用真实模型重新规划和生成前 3 章，对比改造前后：后期词泄露数、前期大词密度、模型审校问题数。

每一期都配单元测试、接口测试，并用真实模型做前后对比（做法同去 AI 味的评测：多次采样、统计、通读）。

## 七、风险与取舍

- **作者要多维护一份计划。** 一键生成加按卷默认值；没有计划的书退回第一期的规则，不会比现在差。
- **收得太紧会写得干。** 悬念本身就是钩子，暗示窗口允许埋线；禁的是「点破」和「大词」，不禁神秘感。
- **泄露词会误报。** 例如「天轨护道盟」含「天轨」。泄露词支持词组和例外；检查结果都附原文，由作者判断。
- **提取会出错。** 揭示进度和角色知识跟现在的设定提取一样，先作为草稿给作者确认。
- **改动面大。** 按期交付，每期独立可用；数据库只加表加列，旧数据不动。
