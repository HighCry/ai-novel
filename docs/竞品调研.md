## 二、各项目最值得看的设计

**webnovel-writer**（星标最多）
- 写章是一条带卡口的流水线：预检 → 刷新本章“合同” → 上下文 Agent 先写一份**写作任务书** → 起草 → 多维审查（有阻断级问题就停）→ 润色排版 → 提取事实 → 生成“章节提交” → 同步到状态、索引、摘要、长期记忆 → 备份。
- “怎么写”和“写了什么”分开：文笔自由发挥，但发生过的事实必须登记、过审、入账。
- **追读力系统**：钩子、爽点、微兑现、读者“债务”（答应读者但还没兑现的东西）。
- 审查维度：爽点、一致性、节奏、OOC、连贯性、追读力。
- 37 个题材模板，可以混搭；**项目学习**：把这本书里好用的写法记进长期记忆。
- 每次任务结束给一份面向作者的报告（已完成 / 部分完成 / 需要你处理 / 未完成）；失败后从可信断点继续。

**AI_NovelGenerator**
- 写一章分两步：先生成本章细纲，再生成正文；每章可以写“本章指导”。
- 定稿时更新全局摘要、人物状态、向量库、剧情要点；一致性校对是可选的一步。

**Long-Novel-GPT**
- 自上而下逐层扩写（大纲 → 剧情 → 正文），支持对选中部分重新生成。
- 可以**查看实际发送的提示词**；创作时**实时显示调用费用**；社区贡献的提示词库（比如“模仿某作者风格”“润色初稿”）。

**NovelWriter**
- 世界模型 = 实体 + 关系 + 体系规则；从正文或设定集自动提取，**提取结果是草稿，审核后才入库**。
- 两个工作台：Studio 日常写作、多版本续写对比；Atlas 专门治理设定。
- 只读的研究助手（找 → 打开 → 阅读），只给建议卡片，不能直接改数据。

**OrisonSpace**：IDE 式编辑器（分屏、多标签、命令面板）；基于 git 的提交、分支、diff 和时间线；DOCX 导入导出。

**wenmai（脉络）**
- **访谈式开书**：AI 一次只问一个问题，给 2～4 个选项，回答自动写进设定、人物、关系和大纲。
- **关系图谱**：可视化编辑，节点位置会记住；一致性检查发现问题时在图上标红相关节点。
- **完结模式**：说“大结局”后，下一章必须收束所有线索，写完自动标记完本。
- 生成前**预估费用**，生成后记录模型返回的实际用量。
- 规则版一致性检查：不可变外貌消失、明确不喝酒的人喝酒、已死亡角色还在行动、已断绝的关系表现亲密、代词或身份漂移。

**PlotPilot（墨枢）**
- 规划层级：部 / 卷 / 幕 → **幕级节拍表** → 逐章生成。
- 每章写完：摘要、事件、三元组（主体-关系-客体）、伏笔四路回写，再给章节打**张力分**（0～10），形成“张力心电图”，低谷自动诊断。
- 文风漂移检测：当前章和风格基准做相似度比较，偏离太多就触发定向修写。
- **20 多个提示词接点**都能用 YAML 提示包覆盖（系统提示、声线锚点、节拍约束、字数层级、模型参数）。
- 伏笔注册表三态：开启 / 悬置 / 消费；人物档案有“POV 防火墙”和“登场频率调度”。
- 工程上：连续失败自动熔断、阶段检查点可恢复、SSE 实时推送阶段和 token 消耗。

**StoryForge（草苔）**（MIT，后端也有 Rust）
- “幕前 / 幕后”双界面：幕前是沉浸式写作（纸张配色、大字号、禅模式），幕后是设定工作室。
- **幽灵文本续写**：Ctrl+Enter 后，AI 续写以灰色斜体预览在光标后，Tab 接受、Esc 拒绝。
- 编辑器里输入 `/` 唤出指令框，自然语言指令由“意图引擎”分派到续写、润色等动作。
- **拆书**：分析一本现成小说，分步提取元信息、世界观、人物、章节概要、故事线，有进度和取消。
- **修订模式**：AI 改动按插入/删除逐条接受或拒绝；场景批注（备注/待办/警告/灵感）。
- **人物动态状态 6 字段**：位置、实力等级、身体状态、心理状态、关键物品、近期事件，记录更新于第几章，可手动修正。
- 追读力：钩子（悬念/冲突/转折）、爽点（打脸/收获/揭秘）、微兑现、债务（带“利息”）、0～100 综合分和趋势图。
- 记忆检索：中文二元组分词 + 向量 + RRF 融合 + 图谱扩展 + 预算控制；场景模型有“戏剧目标、外部压迫、冲突类型（11 种）”。
- 三审流水线：修稿 → 审稿（多维评分 + 问题列表）→ 定稿（后处理步骤逐个记录成功失败）。

**novel-studio**
- 重要人物各自是一个 Agent，只知道自己的档案、目标、资源、已知事实；**世界裁判**只裁决结果，不替人物改意图，用来防止“角色降智”和“提前知道秘密”。
- 结构化台账：人物连续性、关系、**资源（金额、数量）**、伏笔、世界变化。
- 每章四问：事实对不对、故事成不成立（目标、阻力、行动、转折、关系位移、读者回报、章末推力）、文字像不像小说（流程报告、过度解释、同构节奏、对白传送带）、审的是不是同一版正文。
- **跨章文风记忆**：识别跨章节逐字重复、非必要的口头禅、同构的开头和结尾。
- 明确写了：外部 AI 检测只作为用户可选的抽查，不会自动针对检测器优化。

**Novel-OS**
- 五个 Agent（架构师、写手、编辑、守护者、策展人），每个提示都有**输出合同**，强制输出可解析的状态更新块。
- **确定性连续性引擎**（免费、即时，在 LLM 检查之前跑）：剧情线沉寂超过 3 章、超过计划回收章节仍未回收、伏笔无回收、主要人物超过 5 章未出场、主角从未登场、已死亡人物仍有活动状态、主要人物没有填“内在欲望”。
- 编辑 Agent 五种模式：逐句、结构、节奏、对白、张力。

**novel-engine**
- 七人编辑部：故事教练、代笔（先访谈学习作者声音）、**冷读者**（不看任何设定，只说读者感受）、结构编辑、**任务官**（把所有反馈变成有优先级的修订计划）、文字编辑（附风格表）、出版人（书名、简介、关键词、封底文案）。
- 作者自己改过的章节有“已编辑”标记和 diff，AI 修订时能看到作者的改动。
- **意象与高频词台账**：全书追踪反复出现的意象、伏笔和用滥的词；**系列共享设定**；Ctrl+K 命令面板；所有 Agent 指令都是可编辑的文本文件。

**Inxtone**：五层优先级上下文（本章与上一章 1000 → 人物关系地点 800 → 伏笔钩子 600 → 体系规则 400 → 作者置顶 200），超预算从低优先级截断；伏笔生命周期“埋 → 提 → 收”，有逾期检测和钩子强度评分。

**Novelcrafter**（商业）
- Codex：别名自动识别、全文**提及追踪**和提及时间线、大小写敏感与排除列表（避免常用字误匹配）。
- **Progressions**：设定的变化挂在某个场景上，AI 只有在写这个场景及之后的内容时才看得到；回头改前面的章节时不会泄露后面的设定。
- 场景节拍：作者告诉 AI 接下来发生什么；**自定义提示词 + 可复用提示词组件 + 提示词预览**；从笔记或聊天里提取设定条目。

**Sudowrite**（商业）：Story Bible 链式生成（灵感 → 题材 → 文风 → 梗概 → 人物 → 世界观 → 大纲 → 场景 → 正文），每个字段都有“生成”和“按指令重写”；“匹配我的文风”从样章提取文风；生成场景和正文时只带明确提到的人物和设定。

## 三、对比：我们（v0.1）和成熟项目

| 能力 | 我们现在 | 成熟项目的做法 | 差距 |
| --- | --- | --- | --- |
| 开书 | 六步向导 | 访谈式一问一答（wenmai）、一句话直出设定和第一章（StoryForge）、Story Bible 链（Sudowrite） | 小 |
| 写一章 | 按章纲直接出正文 | **先出节拍/细纲再写正文**（AI_NovelGenerator、PlotPilot、Novelcrafter、Sudowrite），写前生成任务书（webnovel-writer） | **大** |
| 人物状态 | 一个“当前状态”文本框 | 6 个结构化字段（StoryForge）、**随章节演变**（Novelcrafter）、知识边界（novel-studio） | **大** |
| 人物关系 | 只能写在描述里 | 关系表 + 可视化图谱（wenmai、StoryForge、webnovel-writer） | 大 |
| 伏笔 | 未回收/已回收/放弃，30 章提醒 | 埋-提-收三态、计划回收章节、沉寂检测、读者债务（PlotPilot、Inxtone、Novel-OS、StoryForge） | 中 |
| 前文检索 | BM25（中文二元组） | BM25 + 向量混合、图谱扩展；多数项目没配向量时也退回关键词检索 | 中 |
| 一致性 | AI 检查 + 不可变特征 | 再加一层**免费的规则检查**（Novel-OS、wenmai） | 中 |
| 质量评估 | 本地文字检查 + AI 审稿打分 | **每章张力/追读力打分并画趋势**（PlotPilot、StoryForge、webnovel-writer）、跨章重复检测（novel-studio） | 中 |
| AI 修改的采纳 | 整段替换，改前自动快照 | **逐条接受/拒绝的修订模式**（StoryForge）、diff（novel-engine、OrisonSpace） | 中 |
| 提示词 | 写死在代码里，只能看上下文 | **可编辑的提示词模板 + 发送前预览**（PlotPilot、Novelcrafter、Long-Novel-GPT、novel-engine） | **大** |
| 费用 | 只记字数 | 预估费用 + 记录模型返回的实际 token（wenmai、Long-Novel-GPT、novel-engine） | 中 |
| 导入旧稿 | 自动拆章分卷 | **拆书**：批量建立设定、摘要、故事线（StoryForge、novel-engine、NovelWriter） | 大 |
| 编辑器 | 普通文本框 + 快捷键 | 幽灵文本、`/` 指令、Ctrl+K、设定名高亮和悬停卡片 | 中 |
| 题材 | 只有题材名称 | 37 个题材模板（套路、爽点、节奏、禁忌） | 中 |
| 批量写作 | 只有批量章纲 | 带审查卡口、检查点和断点续跑的流水线 | 后期 |
| **投稿** | 番茄/起点格式导出 + 投稿检查 + AI 使用记录 | 这些项目都没有 | 我们领先 |
| **部署** | 单个 10 MB exe，零依赖 | 多数要 Python + Node + 向量库/Docker | 我们领先 |
| **酒馆迁移** | 角色卡、世界书导入 + 角色对话 | 这些项目都没有 | 我们领先 |

结论：骨架和基础功能已经齐全，但成熟项目在三件事上明显更深：**写章前的规划**（节拍/任务书）、**设定的时间维度**（状态随章节演变、关系、知识边界）、**可定制性**（提示词模板）。另外，它们都经过了几个月的真实使用和 issue 反馈，我们还没有用真实模型跑过。

## 四、值得借鉴的功能（按优先级）

**P0：直接提升写作质量和长篇正确性**
1. **两段式写章**：先生成本章节拍（5～8 个场景节拍：目标、冲突、转折、钩子），作者改完再写正文。来源：AI_NovelGenerator、PlotPilot、Novelcrafter、Sudowrite、webnovel-writer。
2. **设定随章节演变**：人物状态按章节存历史；写第 N 章时只用第 N 章之前的状态，回头改前文不泄露后面的剧情。来源：Novelcrafter progressions、StoryForge。
3. **人物状态结构化**：位置、实力、身体、心理、关键物品、近期事件、知道/不知道的秘密；定稿时按字段提取。来源：StoryForge、novel-studio。
4. **免费的规则连续性检查**：伏笔沉寂 N 章、超过计划回收章节、主要人物 N 章没出场、已死亡人物出场、人物缺少动机。来源：Novel-OS、wenmai。
5. **提示词模板可编辑 + 发送前预览**：所有提示词在设置里可改、可恢复默认，每次生成可以看完整提示词。来源：PlotPilot、Novelcrafter、Long-Novel-GPT、novel-engine。
6. **章节张力/追读力曲线**：定稿时顺带打分（钩子类型、爽点类型、张力 0～10），全书画成曲线，低谷提醒。来源：PlotPilot、StoryForge、webnovel-writer、Inxtone。

**P1：体验和效率**
7. **修订模式**：润色、改写结果以 diff 展示，按句子逐条接受或拒绝。来源：StoryForge、novel-engine。
8. **拆书 / 导入后自动建档**：导入旧稿后批量生成章节摘要、提取人物和伏笔（显示进度，可取消，结果先作为草稿等审核）；也可以拆对标书学结构。来源：StoryForge、novel-engine、NovelWriter。
9. **人物关系**：关系表（双方、关系类型、从第几章开始、当前状态）+ 关系图，一致性问题在图上标红。来源：wenmai、StoryForge。
10. **真实用量和费用**：记录接口返回的 token 用量，按模型单价算费用，生成前预估。来源：wenmai、Long-Novel-GPT、novel-engine。
11. **跨章重复检测**：全书层面的口头禅、反复出现的句式、同构开头结尾。来源：novel-studio、novel-engine。
12. **文风提取**：从样章分析出文风画像（句长、对话比例、视角、语气、常用词），写进提示词，并检测后续章节是否偏离。来源：Sudowrite、StoryForge、PlotPilot。
13. **完结模式**：最后一章强制收束所有未回收伏笔。来源：wenmai。
14. **题材模板**：每个题材写清核心爽点、常见套路、节奏建议、雷区和开篇建议，开书和写作时注入。来源：webnovel-writer、StoryForge。

**P2：大功能，后续再做**
15. 编辑器升级：幽灵文本续写、`/` 指令、Ctrl+K 命令面板、设定名高亮和悬停卡片（需要把文本框换成 CodeMirror 这类编辑器）。
16. 向量检索：配置 Embedding 后和 BM25 做 RRF 混合。
17. 人物推演：让主要人物按各自的目标和已知信息推演下一步行动，给章纲提供素材。来源：novel-studio。
18. 批量写作流水线：规划 → 起草 → 审查（有阻断问题就停）→ 作者确认 → 定稿，带检查点和断点续跑。
19. 冷读者反馈 + 修订计划、系列共享设定、写法库（项目学习）、事件时间线、版本分支。

## 五、不借鉴的

- **规避 AI 检测的功能**：不做。部分项目有“Anti-AI 终检”一类的步骤，我们只保留针对文字质量的检查（套话、句式重复、流程化叙述），不做针对检测器的优化。
- **代码直接搬运**：webnovel-writer（GPL-3.0）、AI_NovelGenerator（AGPL-3.0）、NovelWriter（AGPL-3.0）、novel-engine（AGPL-3.0）的代码一旦搬进来，整个项目都要按 GPL/AGPL 开源；Long-Novel-GPT 和 wenmai 没有许可证，默认保留所有权利；PlotPilot 禁止商用。这些项目**只借鉴设计思路，不复制代码和提示词原文**。StoryForge、Novel-OS（MIT）和 OrisonSpace、novel-studio（Apache-2.0）可以参考代码，但我们是 Rust + 原生 JS，实际上也是按思路重写。
